# Требования к ACMS Censor

## User Stories

### US-01. Цензура изображения

Как редактор,
я хочу автоматически скрывать на изображении объекты выбранных категорий,
чтобы сократить время подготовки материала к публикации.

Критерии приёмки:

- Система принимает изображение, список категорий для цензуры и способ скрытия: размытие или пикселизацию.
- На тестовом изображении с обнаруженным объектом выбранной категории соответствующая область скрывается указанным способом; при отсутствии совпадений сохраняется изображение без изменений.
- Если файл невозможно прочитать или модель не может выполнить анализ, система сообщает об ошибке и не выдаёт задание за успешно завершённое.

### US-02. Цензура аудио

Как автор контента,
я хочу заменять нежелательные фразы в аудиозаписи звуковым сигналом,
чтобы подготовить запись к публикации без ручного редактирования каждого фрагмента.

Критерии приёмки:

- Система принимает аудиофайл и распознаёт речь с временными границами слов или фраз.
- В тестовой записи распознанная нежелательная фраза заменяется сигналом в соответствующем интервале; остальные фрагменты записи сохраняются.
- Если обработка аудио завершается ошибкой, пользователь получает сообщение об ошибке вместо ссылки на готовый результат.

### US-03. Сохранение результата

Как модератор,
я хочу сохранять обработанный медиафайл,
чтобы проверить его и передать для дальнейшей публикации.

Критерии приёмки:

- После успешной обработки изображения, аудио или видео система предоставляет соответствующий выходной файл.
- Сохранённый результат открывается как медиа того же типа, что и исходный файл; исходный файл не перезаписывается.
- До завершения обработки и при ошибке система не предоставляет результат как готовый к использованию.

## Use Case

### UC-01. Автоматическая цензура изображения

**Связанные User Stories:** US-01, US-03.

**Актор:** редактор.

**Цель:** получить отдельный файл изображения со скрытыми объектами выбранных категорий.

**Предусловие:** редактор подготовил изображение; приложение и модель обнаружения объектов доступны.

**Основной сценарий:**

1. Редактор передаёт изображение приложению, выбирает категории для цензуры и способ скрытия.
2. Приложение проверяет, что изображение читается и параметры обработки корректны.
3. Приложение передаёт изображение модели обнаружения объектов.
4. Модель возвращает категории и координаты обнаруженных объектов.
5. Приложение отбирает объекты выбранных категорий и скрывает их области размытием или пикселизацией.
6. Приложение сохраняет обработанное изображение в отдельный файл и сообщает об успешном завершении.
7. Редактор сохраняет результат и проверяет изображение перед публикацией.

**Альтернативные сценарии:**

- **A1 — некорректный файл или параметры, шаг 2:** приложение сообщает причину отказа; редактор исправляет параметры или передаёт другой файл и повторяет запуск.
- **A2 — ошибка модели, шаг 4:** приложение сообщает, что анализ не завершён; результат не предоставляется, редактор может повторить обработку или отредактировать изображение вручную.
- **A3 — нет объектов выбранных категорий, шаг 5:** приложение сохраняет отдельную копию изображения без изменений и сообщает об отсутствии совпадений.
- **A4 — ошибка обработки или сохранения, шаги 5–6:** приложение сообщает об ошибке; задание не отмечается как успешно завершённое.

**Результат:** редактор получает отдельный файл изображения с применённой цензурой либо копию без изменений, если совпадений нет; при ошибке получает сообщение без готового результата. Исходный файл сохраняется.
